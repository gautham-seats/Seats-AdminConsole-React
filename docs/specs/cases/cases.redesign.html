Cases — redesign variants

Three directions each for Workflow Admin and Student Workflow. The option inventory below is taken from the actual Polymer components, not from the build plan — the plan turned out to be wrong in several places.

Built on existing tokens and shared parts: brand #1566a2 for active and primary only, neutral greys otherwise, motion 150–300 ms on ease-premium, reduced-motion safe. No new component families.

Corrections found by reading the legacy source. These differ from the written spec, so any redesign built on the spec alone would have been wrong:

· The Add/Edit Workflow dialog has exactly one field — Name (required, max 50). Not type, dates, contact group or faculty e-mail flags.
· Student Workflow's table has 8 columns, not 4.
· Student search is one autocomplete, not two inputs — it routes to number-or-name by whether you typed a digit.
· The workflow stats are grid columns in legacy, not a summary strip.
· Status options are Live / Disabled.
· For General and Engagement workflow types, seven columns blank out and the Status, Approval and Constraints controls disappear entirely.

Page 1 — Workflow Admin

5 levels deep

Legacy spreads this over 11 pages: a workflow grid, then Stage Groups → Stages → Rule Groups → Rules / Triggers → Attributes, plus Constraints and Manual Interventions. Each level is a full page load with a Back button, and four orphaned "Change…" modals were an abandoned attempt at moving sideways. Each variant below solves that differently.

A · Column Cascade

Every level is a column. Choosing an item slides the next one in. The whole path — and every sibling at every level — stays on screen, so the eleven page loads collapse into one view.

Every list, in every variant

Loading · empty · error with Retry · populated — four designed states, not one happy path. Every control defines resting, hover, pressed, focus ring, disabled, loading, transition and reduced-motion behaviour.

Legacy defects we deliberately do not copy

DefectWhat we do instead
Approved dropdownIt compares against the wrong field, so the saved approval never displays correctly. React binds the right field
Lost validationThe two Move validation messages are written to an element that does not exist — nobody ever sees them. React shows them on the fields
Hard-coded EnglishThree strings bypass localisation. React uses resource keys
Permission gapsA bug leaves Add / Delete / Edit visible to everyone on Workflow Admin, and 10 of 11 drill-down pages have their permission check commented out. React gates the UI properly — the server already enforces
Duplicate idsTwo grid columns and several inputs share ids. React gives each a unique, labelled control

If you want a steer

Workflow Admin → A (Column Cascade). The genuine pain is five levels across eleven pages, and A is the only one that never hides where you are.
Student Workflow → B (Filter-first Table). Eight columns and bulk actions are exactly what that pattern is for, and it matches every other list in Admin.

If the presentation matters more than daily use, B (Pipeline Canvas) for Workflow Admin is the one people remember — it just costs the most to build.
