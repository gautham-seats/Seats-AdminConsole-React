Timetable needs a backend endpoint

Nothing in the Admin API returns the lectures booked into one room. This tab stays empty until someone adds GET RoomApi/{id}/Timetable — the design is ready for it.

Activity needs a filter the audit API does not have

audit/GetAudit filters by site, type, user and date — but not by one room's id, so it cannot show this room's history. Until it can, this links out to the full Activity Log.

What is real and what is not
  • Details — all four legacy fields, from GET RoomApi/{id}. Real today.
  • Devices — the device list filtered by this room, the same call the Devices page already makes. Real today.
  • Hero: Seats — the capacity field. Devices — the count from that same device call. Last reading — the newest reading date across those devices. All three are real.
  • Hero: Active chip — rooms have no active flag in the API; it would have to be dropped or added.
  • Timetable and Activity — no endpoint exists. Shown as honest empty states rather than invented numbers.
