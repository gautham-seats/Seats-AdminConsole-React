Access Profile — 5 redesigns

Same legacy behaviour and API as today (name, external key, restricted, default landing page, Site Access permissions, and Event / Case / Workflow visibility that appear only when those permissions are on, Copy Profile, Save, Cancel). Only the layout, clarity and motion change. Every sample is clickable: tick permissions, change the landing page, search, switch tabs, press Save.

What is an Access Profile?A named set of rights. Users get one or more profiles; the profile decides what they can open and do in Admin and the website.
Site AccessFor each area (Users, Rooms, Students…) choose actions: Access to open it, then Add, Edit, Delete, Export and extras.
Default landing pageThe page users with this profile see first. It must be an area the profile can Access, otherwise Save warns.
Visibility tabsEvent, Case and Workflow visibility appear only when the matching permission is ticked, and choose which items those users can see.
